# 正式应用统一自定义下拉框设计

## 目标与范围

正式应用中的所有原生 `select` 统一替换为项目自有的 `SelectControl`，不再使用操作系统原生展开菜单。视觉以用户提供的参考图为准：清晰的青绿色焦点边框、白色浮层、浅青色选中项背景、左侧对勾和右侧下箭头。

项目只保留正式应用。删除 `prototype.html`、`web/src/prototype/`、Vite 的 prototype 构建入口，以及只验证 prototype 兼容入口的测试。不得删除或改动正式应用仍在引用的模块。

## 组件设计

扩展 `web/src/features/ui/SelectControl.tsx`，作为正式应用唯一的单选下拉组件。组件接受可访问名称、当前值、选项、变更回调，并支持禁用状态、占位项和适配不同工具栏密度的样式类。

交互要求：

- 点击触发器打开或关闭列表，点击外部或按 Escape 关闭。
- 支持方向键移动高亮项，Enter/Space 选择，Home/End 跳转。
- 打开后确保当前选项可见；选择后关闭并将焦点返回触发器。
- 使用 combobox/listbox/option 语义，并同步 `aria-expanded`、`aria-selected` 和禁用状态。
- 浮层层级高于工具栏和对话框内容，靠近视口边缘时不得被父容器裁切或溢出屏幕。

## 替换范围

替换正式应用中以下场景的原生下拉：查询上下文的数据库、Schema 和表；团队连接筛选；个人配色；连接编辑中的数据库类型和 TLS 模式；表格分页条数；Schema 外键本地字段；以及当前过滤器中已经使用的字段和运算符下拉。

所有业务状态和回调保持不变；仅统一呈现和交互，不改变数据流、默认值或提交逻辑。

## 视觉规则

沿用现有 token，不引入新的 UI 库。触发器尺寸通过紧凑、默认和宽字段样式适配现有布局；边框、圆角、字体和阴影统一由 `workbench.css` 管理。选中项使用主题 accent 的低透明度背景，深色主题采用相同语义 token 自动适配。焦点样式必须清晰可见，并尊重 reduced-motion 设置。

## 清理与验证

删除原型入口及专属源码后，确保构建只输出正式入口。为 `SelectControl` 增加键盘、关闭、禁用和选择行为测试；调整受影响页面测试。最后运行 Web 全量测试、类型检查和生产构建，并扫描正式源码确认不存在原生 `<select>`。
