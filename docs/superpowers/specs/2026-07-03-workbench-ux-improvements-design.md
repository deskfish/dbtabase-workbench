# Database Workbench UX 完善设计

## 背景

现有工作台已经形成连接栏、对象栏和主工作区的三栏结构，并支持 PostgreSQL、MySQL、MongoDB、Redis。此次不做完整视觉换肤，也不修改后端协议，而是在现有设计系统内解决 UI 走查中影响开发效率和操作信心的问题。

`password_hash` 等字段继续按普通数据库字段展示，不加入隐藏、脱敏或导出限制。

## 目标

- 未连接时给出明确入口，消除空白故障感。
- 让 SQL 运行成为编辑器最清晰的主操作。
- 将表结构浏览与编辑拆成两个明确状态。
- 降低宽表浏览时的横向迷失和操作成本。
- 让团队连接全部已复制时呈现清楚的完成态。
- 补齐页签、弹窗和焦点管理的基础无障碍语义。
- 保持现有 API、数据库安全确认和错误处理协议不变。

## 非目标

- 不重构整体三栏信息架构。
- 不更换颜色、字体或完整组件体系。
- 不修改 PostgreSQL、MySQL、MongoDB、Redis 的能力边界。
- 不修改数据库查询、结构变更和连接管理 API。
- 不新增敏感字段识别或展示策略。
- 不将移动端作为本轮验收目标。

## 设计方案

### 未连接首页

未连接时保留连接栏。对象栏不再显示无内容的空白面板，而是显示标题、简短说明和“选择左侧连接”的空状态。主工作区显示三个任务入口：

- `选择连接`：将焦点移到个人连接搜索框或第一条可用连接。
- `新建连接`：复用现有新建连接入口。
- `团队连接`：打开现有团队连接弹窗。

入口使用现有按钮和图标组件，不引入新的页面或路由。

### SQL 工作区

查询工具栏最左侧放置主按钮 `运行`，保留现有停止、刷新、导出和事务操作。按钮显示快捷键提示；支持 `Ctrl/Cmd + Enter` 运行。

默认 SQL 改为注释式引导，不再包含不可执行的 `your_table`：

```sql
-- 从左侧选择一张表，或在这里输入 SQL
```

用户从查询工具栏选择表后，在编辑器仍为默认引导内容时生成：

```sql
SELECT *
FROM schema.table
LIMIT 200;
```

用户已经编辑 SQL 时，选择表只更新查询上下文，不覆盖内容。结果区空状态说明“运行查询后结果会显示在这里”，并展示快捷键。

### 表结构只读态与编辑态

表结构默认进入只读态。字段、索引和关系使用文本单元格、状态图标和只读信息展示；权限与 DDL 保持只读。

结构页顶部提供 `编辑结构` 按钮。进入编辑态后：

- 字段名、数据类型、非空、主键、默认值和注释恢复现有可编辑控件。
- 显示新增、删除字段及索引、关系编辑能力。
- 顶部固定操作区显示 `已修改 N 项`、`预览 SQL`、`放弃`、`保存`。
- `保存` 沿用现有 DDL 预览、风险确认和执行流程。
- `放弃` 恢复最近一次服务端读取的结构。
- 保存成功后刷新数据并返回只读态。

当存在未保存修改时，切换到数据预览、关闭表标签、切换连接或离开页面前必须确认。取消确认时留在当前编辑态。

### 数据表浏览

数据表延续现有网格结构，调整如下：

- 行号列固定在最左侧。
- 存在主键或唯一键时，第一关键列固定在行号列右侧。
- 表头保持吸附；底部草稿操作区、SQL 摘要和分页保持可见。
- 新增、删除、应用、放弃、刷新等核心操作采用图标加文字；低频操作可保留纯图标并提供 tooltip。
- `显示列` 与 `密度` 保留在右侧；筛选状态和排序状态继续显示徽标。
- 不对 `password_hash` 或其他字段做特殊处理。

### 团队连接完成态

团队连接弹窗默认状态筛选为 `可复制`。当存在可复制连接时，保持当前列表与批量复制流程。

当所有连接都已在个人列表时：

- 列表区域显示完成态：`团队连接均已添加到个人列表`。
- 提供 `查看已在个人` 次级操作，将状态筛选切换为 `已在个人`。
- 底部不显示无意义的禁用主按钮，只保留 `关闭`。

搜索后无结果继续使用“没有匹配的团队连接”，与全部完成态区分。

### 无障碍语义与焦点

- 工作区页签使用 `role="tablist"`、`role="tab"`、`role="tabpanel"` 和 `aria-selected`。
- 数据预览/表结构与字段/索引/关系/权限/DDL 使用相同语义。
- 关闭页签使用真实 `button`，不再使用 `i role="button"`。
- 团队连接弹窗支持 `Escape` 关闭、焦点锁定和关闭后焦点归还到触发按钮。
- 方向键可在同一页签组内切换焦点；Enter 或 Space 激活页签。
- 所有新增文字+图标按钮保持现有可见焦点样式。

## 状态与数据流

新增状态均位于前端：

- SQL 默认引导是否仍未被用户编辑。
- 表结构是否处于编辑态，以及基于现有 diff 结果计算的修改数量。
- 团队连接弹窗当前是否为全部完成态。
- 弹窗触发元素和当前焦点，用于关闭后恢复。

现有 API 调用、错误对象、DDL 风险确认和查询执行链路不变。新增状态不得吞掉现有错误；错误继续显示在当前工作区的消息区域。

## 组件边界

- `App` 负责未连接首页入口、工作区一级页签语义、关闭表标签前的未保存保护，以及 SQL 表选择与编辑器模板联动。
- `SchemaWorkspace` 负责只读/编辑态、修改计数、放弃、保存和二级页签语义，并通过回调向 `App` 暴露未保存状态。
- `SqlEditor` 负责运行主按钮、快捷键和默认引导内容。
- `TableView` 负责固定列、吸附区域和文字化操作按钮。
- `TeamConnectionsDialog` 负责默认筛选、完成态、Escape、焦点锁定和焦点恢复。
- 共享页签键盘行为提取为小型 UI helper 或 hook，避免三处重复实现。

## 测试策略

### 组件测试

- 未连接首页三个入口可访问且触发正确动作。
- 默认 SQL 为注释引导；选择表只在 SQL 未编辑时插入模板。
- 运行按钮和 `Ctrl/Cmd + Enter` 调用同一执行路径。
- 表结构默认只读，进入编辑态后控件出现；放弃恢复数据；保存后返回只读。
- 存在未保存修改时，切换视图和关闭标签需要确认。
- 数据表行号与关键列具有固定列 class；核心操作显示文字标签。
- 团队连接默认显示可复制项；全部已复制时显示完成态且不显示禁用主按钮。
- 页签暴露正确 role、`aria-selected` 和键盘行为。
- 弹窗 Escape、焦点锁定和焦点恢复可用。

### 回归验证

- 运行完整前端测试。
- 运行 TypeScript 构建。
- 在部署页面按未连接、连接、SQL、数据预览、表结构和团队连接路径回归桌面端。
- 验证 PostgreSQL、MySQL、MongoDB、Redis 的既有入口仍可用。

## 验收标准

- 未连接页面不存在无说明的大面积空白栏。
- SQL 运行操作在工具栏中具有最高视觉优先级，并支持快捷键。
- 默认 SQL 不包含 `your_table`；选择表不会覆盖用户已有 SQL。
- 表结构初始不可编辑，必须显式进入编辑态。
- 未保存结构修改不会因切换或关闭无提示丢失。
- 数据表关键列和底部操作在滚动时保持上下文。
- 团队连接全部已复制时展示完成态，不展示禁用复制主按钮。
- 页签和团队弹窗通过组件测试覆盖基本键盘与焦点行为。
- 现有 API 和危险操作确认行为保持不变。
